# 封测发布与故障处理清单

## 发布前

- 从 `.env.production.example` 创建 `.env.production`，执行 `pnpm prod:check`，确认域名均为 HTTPS 且没有示例密钥。
- 执行 `pnpm prod:restore:test -- backups-production/<文件>.dump`，确认最近备份可以恢复到隔离库。
- 在运营后台“封测发布”确认数据库、迁移、内容、备份和当前部署均通过，没有发布阻断项。
- 检查 AI 配置、当前内容版本、待处理反馈、学习质量问题和严重客户端错误。
- 使用微信开发者工具完成游客首训、微信登录、同步、AI 点评、复习和注销验收。
- 使用生产 API 地址和明确版本号构建小程序；开发者工具手动上传体验版并设置微信灰度范围。

## 发布后观察

- 首小时检查 API、数据库、内容和 AI 状态。
- 确认 `/health/live` 与 `/health/ready` 均返回 200，HTTPS 证书和后台域名正常。
- 关注严重错误、错误指纹增长和集中受影响页面。
- 错误处理中填写内部备注；确认修复后标记“已解决”。
- 客户端新发生的同指纹问题会重新进入待处理状态。

## 回滚与紧急下架

- 内容问题：在当前发布版本找到训练并执行下架；该操作会立即产生更高版本。
- 普通内容回退：从历史版本创建回滚草稿，校验并发布，不修改历史快照。
- API 故障：停止新版本发布，保留小程序本地训练能力，恢复后检查同步 outbox。
- 应用故障：执行 `pnpm prod:rollback -- <上一镜像标签>`；只回滚应用镜像，不逆向执行数据库迁移。
- 数据异常：不要直接覆盖正式库；先通过 `pnpm prod:restore:test` 在 `microly_restore` 验证备份，再制定正式恢复步骤。

## 运行开关

- 维护模式仅暂停不兼容的联网写入，课程读取、本地训练、退出登录和账号注销保持可用。
- 暂停账号同步后，小程序必须保留完成记录与统一同步 outbox，恢复开关后自动重试。
- 最低支持版本只限制旧版本联网写入，不清除本地训练和内容缓存。
- 微信登录、AI 点评与反馈可以单独关闭；每次变更必须填写原因并保留审计记录。

## 隐私边界

- 错误报告仅包含分类、页面、版本、网络类型、安全错误码和不可逆指纹。
- 不记录主动表达、请求正文、token、微信 code/openid、AppSecret 或模型原始输出。
- 用户反馈正文只能在反馈处理页面查看，不进入错误监控。
