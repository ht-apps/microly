# 01 需求分析

## 1. 背景与机会

很多用户有持续学习的愿望，但完整课程、长视频和系统性书籍需要连续时间与较高启动成本。通勤、排队、午休等碎片时间虽然频繁，却难以承载传统学习形式。另一方面，普通知识卡片和背诵工具通常偏被动：用户“看过”了内容，却不一定理解、记住或能在真实场景中使用。

生成式 AI 显著降低了情景变体、错误选项、反馈文本和个性化练习的生产成本，但“能生成内容”本身不是用户价值。产品需要解决的是：

- 把模糊的学习意愿转成每天可以立即开始的任务；
- 让短内容具备目标、递进、练习和复习，而不是成为另一种信息流；
- 控制 AI 内容的准确性、稳定性、成本和安全风险；
- 让用户感受到现实能力的变化，而不只是连续打卡。

## 2. 问题定义

### 2.1 用户问题

目标用户在以下链路中持续流失：

```text
想提升能力
  → 不知道从哪里开始
  → 没有完整时间
  → 选择了过长或过泛的内容
  → 看完没有练习
  → 很快忘记
  → 感觉没有效果
  → 放弃学习
```

### 2.2 产品问题

产品需要验证三个核心假设：

| 编号 | 假设 | 验证信号 |
| --- | --- | --- |
| H1 | 用户愿意用 3 分钟完成一个结构化情景训练 | 首次训练完成率、单组完成时长 |
| H2 | 情景练习比纯知识阅读更容易形成次日回访 | D1 留存、7 日有效训练天数 |
| H3 | 复习和主动表达能让用户感知“会用了” | 复习完成率、主动练习率、自报实际使用率 |

若 H1 不成立，应先优化首次体验；若 H1 成立而 H2 不成立，应调整课程价值、提醒和进度反馈；若 H1/H2 成立但 H3 不成立，说明产品更像内容消费，需要强化练习与迁移。

## 3. 产品定位

### 3.1 定位陈述

面向希望提升职场沟通能力、但难以投入连续学习时间的年轻职场人，微习提供每天 3 分钟的真实情景训练、结构化反馈和间隔复习。与随机知识卡片和长课程不同，微习围绕明确技能路径组织内容，帮助用户把表达原则迁移到现实场景。

### 3.2 品牌表达

- 中文名：微习
- 英文名：Microly
- 主口号：每天 3 分钟，练会一个小技能。
- 首发副标题：真实职场情景，练出清晰表达。
- 品牌关键词：轻量、可信、可练、成长、克制
- 避免使用：高情商话术、操控人心、万能模板、保证晋升

### 3.3 核心价值主张

| 用户顾虑 | 产品回应 |
| --- | --- |
| 我没时间 | 默认一组约 3 分钟，可随时暂停 |
| 我不知道学什么 | 提供清晰的技能路径和今日任务 |
| 我看过但记不住 | 根据作答与时间安排复习 |
| 我知道道理但不会说 | 提供情景选择与主动表达练习 |
| AI 内容不可信 | 正式课程经过规则校验与人工审核 |

## 4. 用户研究假设

### 4.1 核心用户

**1～5 年工作经验的知识工作者**，尤其是需要跨团队协作、向上汇报或处理模糊需求的人群。

典型特征：

- 每天可支配学习时间短且不固定；
- 已经意识到表达与协作是工作瓶颈；
- 愿意使用工具改善工作，但不愿完整学习一门沟通课程；
- 对“直接可用的表达”和具体反馈有兴趣；
- 主要在微信生态中完成轻量内容消费和分享。

### 4.2 次级用户

- 刚入职或正在实习的新人；
- 第一次担任管理者的团队负责人；
- 产品、研发、设计、运营等高协作密度岗位；
- 有面试、述职、跨部门推动等短期明确目标的人群。

### 4.3 非目标用户（MVP）

- 寻求心理诊断、劳动法律意见或危机干预的人；
- 需要系统认证、考试提分或企业培训管理的人；
- 希望自由生成任意专业课程的人；
- 需要实时语音陪练的人。

## 5. 核心使用场景

| 场景 | 触发 | 用户任务 | 成功结果 |
| --- | --- | --- | --- |
| 通勤训练 | 早晚通勤，时间零散 | 完成今日 1 组训练 | 3 分钟内完成并理解一个原则 |
| 工作前准备 | 即将汇报、开会、催进度 | 学习相关专题场景 | 获得一句可迁移的表达框架 |
| 午间复习 | 有 1～2 分钟空闲 | 复习错题或薄弱技能 | 正确回答并恢复记忆 |
| 遇事后复盘 | 刚经历沟通不畅 | 查找相似情景并练习 | 识别问题并形成替代表达 |
| 分享挑战 | 发现有讨论价值的题目 | 分享不含答案的挑战 | 好友进入答题，形成自然传播 |

## 6. 首发领域选择

| 领域 | 即学即用 | 适合互动 | 内容风险 | 差异化空间 | MVP 结论 |
| --- | ---: | ---: | ---: | ---: | --- |
| 职场沟通与表达 | 高 | 高 | 中 | 高 | 首发 |
| AI 办公效率 | 高 | 中 | 中 | 中 | 第二课程线候选 |
| 生活场景英语 | 高 | 高 | 低 | 低 | 需语音能力后再做 |
| 历史与通识 | 低 | 中 | 中 | 低 | 暂不做 |
| 编程 | 中 | 中 | 中 | 低 | 小程序内实践受限 |
| 泛心理学 | 中 | 高 | 高 | 中 | MVP 排除 |
| 冷知识 | 低 | 中 | 中 | 低 | 仅可作为传播内容，不做核心课程 |

职场沟通的优势是现实反馈周期短、适合情景选择、用户容易感知价值；风险在于不存在适用于所有组织关系的唯一话术。因此反馈必须解释适用条件和权衡，避免将“推荐回答”包装成绝对正确答案。

## 7. MVP 范围

### 7.1 必须具备

- 微信授权或游客试用；
- 首次偏好选择；
- 今日训练：情景、选择、反馈、原则、迁移练习；
- 结构化课程路径和进度；
- 错题与收藏；
- 基础间隔复习；
- 受约束的 AI 表达点评；
- 连续学习与周进度；
- 情景挑战分享；
- 内容发布所需的最小后台能力；
- 核心行为埋点和基础运营数据。

### 7.2 明确不做

- 无限下拉知识流；
- 用户任意输入主题生成整门课程；
- 开放式 AI 聊天老师；
- 社区、评论、私信；
- 好友 PK、排行榜、复杂积分商城；
- 企业组织、管理员与培训报表；
- 全量实时个性化生成；
- 心理、医疗、金融、法律类建议；
- 原生 App；
- MVP 阶段支付闭环。

### 7.3 首批内容规模

首发 4 个章节，每章 5 个课节，每课节 3～5 组训练，总量约 80 组：

1. 清晰汇报；
2. 边界沟通；
3. 提出不同意见；
4. 推动他人行动。

公测前至少准备 30 组高质量种子训练，足以支持第一轮核心体验测试；正式首发前扩充至约 80 组。

## 8. 业务目标与成功标准

### 8.1 MVP 目标

1. 证明用户愿意完成情景式微训练；
2. 找到驱动次日和一周回访的内容与机制；
3. 证明主动表达点评有使用价值且成本可控；
4. 建立可持续生产、审核和迭代内容的流程。

### 8.2 建议验证阈值

以下是封闭测试阶段的决策阈值，不是行业基准；样本量不足时只用于发现方向：

| 指标 | 目标 | 低于目标时优先检查 |
| --- | ---: | --- |
| 首次训练开始率 | ≥ 70% | 引导长度、首页信息、登录门槛 |
| 首次训练完成率 | ≥ 65% | 卡片数量、反馈长度、交互理解 |
| 单组中位完成时长 | 2～5 分钟 | 难度、文字密度、AI 等待时间 |
| 次日留存（完成过首训用户） | ≥ 30% | 今日价值、提醒、次日内容承接 |
| 7 日内完成 ≥3 天占比 | ≥ 20% | 课程递进、回访理由、任务负担 |
| 主动表达练习提交率 | ≥ 25% | 输入门槛、隐私顾虑、点评预期 |
| 到期复习完成率 | ≥ 25% | 复习入口、数量控制、收益反馈 |
| 严重内容投诉率 | < 0.1% | 审核、敏感场景、表述绝对化 |

## 9. 约束与风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| AI 建议不准确或过度绝对 | 伤害信任，可能误导用户 | 离线审核、展示适用条件、用户反馈与快速下架 |
| 内容看似丰富但无递进 | 留存低，无法形成能力感 | 先设计能力模型，再生产卡片 |
| 实时点评延迟或成本过高 | 中断体验，商业不可持续 | 限字数、结构化输出、缓存、每日额度、规则降级 |
| 用户输入含公司或个人隐私 | 数据风险 | 明示提醒、最小采集、日志脱敏、删除入口 |
| 微信名称或品牌占用 | 上线与传播受阻 | 上线前核验小程序名、商标、域名和应用商店 |
| 游戏化喧宾夺主 | 为打卡而非学习 | 奖励完成和复习，不做高压断签惩罚 |
| 分享暴露作答结果 | 用户不愿分享 | 默认只分享挑战，不展示错误率与原始输入 |

## 10. 待验证问题

需求阶段不能仅靠内部判断，封测前应访谈 8～12 名目标用户并验证：

1. 用户最近一次真实的职场沟通困难是什么？
2. 用户当前如何准备或复盘这类场景？
3. 用户愿意每天训练，还是只在遇到问题时查找？
4. 用户更看重参考答案、解释、表达框架还是 AI 点评？
5. 哪些输入内容用户认为过于隐私？
6. “连续学习”会鼓励用户还是造成压力？
7. 用户愿意为什么付费：完整课程、专题包、AI 点评还是报告？
